# 04 — Internationalization

## v1 decision

- **UI language**: Uzbek, **Latin script**, only.
- **Content language**: all questions/options/explanations/rules authored in Uzbek (Latin).
- **Russian and Cyrillic**: **v2**. The schema is already translation-ready, so adding
  Russian is **additive** (new translation rows + a UI catalog), **not** a migration of core
  tables.

## Content schema is translation-ready now (not deferred)

Unlike an earlier draft, the language split is built into the v1 schema (see
[02-domain-model.md](02-domain-model.md)). Language-neutral facts live on the base rows;
all human-readable text lives in translation tables keyed by `(entity, language)`:

```
Question              # category, topic, media_id, difficulty, is_sign_question ...
QuestionTranslation   # (question_id, language) -> prompt, short_explanation
AnswerOption          # position, is_correct  (correctness is language-neutral)
AnswerOptionTranslation  # (answer_option_id, language) -> text, explanation
Rule                  # code, source_url, effective dates ... + text_uz (ru text added in v2)
```

v1 writes only `language = "uz"` rows. Russian later adds `ru` rows against the **same**
base records. Media is **shared** across languages unless an image bakes in text (avoid).

For `Rule`, v1 keeps the rule text as `text_uz`. When Russian is added, either add a
`text_ru` column or (preferred, consistent with the pattern) a `RuleTranslation` table; the
decision is left to v2 but does not block v1.

## UI strings

- All user-facing strings go through a **single string catalog**, not inline literals — even
  with one language in v1. This is what makes adding Russian cheap.
- Frontend: a typed `uz` dictionary (e.g. `src/i18n/uz.ts`) keyed by string id, via a small
  `t(key)` helper. A `lang` value on the profile selects the catalog; v1 always resolves
  `uz`.
- Backend user-facing messages (validation/error `detail`) are written in Uzbek and kept
  centralised for later translation.

## Formatting and copy conventions (Uzbek)

- Uzbek Latin orthography (o', g', sh, ch, ng).
- Terminology: **YHQ** (Yo'l Harakati Qoidalari), **haydovchilik guvohnomasi** (licence),
  **nazariy imtihon** (theory exam), **chorraha** (intersection), **yo'l belgisi** (road
  sign), **to'xtash/to'xtab turish** (stopping/parking).
- Result/dashboard copy: **O'tdingiz** (pass) / **Yiqildingiz** (fail),
  **Imtihonga tayyorlik** (exam readiness), **Boshlang'ich daraja** (initial level),
  **Ma'lumot yetarli emas** (not enough data), **Xatolar** (mistakes).

## Non-goals (v1)

- No language switcher in the UI (single language).
- No auto-translation of content. Russian content, when added, is authored/reviewed by a
  human (LLM drafts allowed but must be verified — see [00-overview.md](00-overview.md)).
