# 04 — Internationalization

## v1 decision

- **UI language**: Uzbek, **Latin script**, only.
- **Content language**: all questions/options/explanations/rules/alt text authored in Uzbek.
- **Russian and Cyrillic**: **v2**, but the schema is fully translation-ready now, so adding
  Russian is **additive** (new translation rows + a UI catalog), not a core-table migration.

## Content schema is fully translation-ready (all text in translation tables)

Language-neutral facts live on base rows; **all** human-readable text lives in per-language
translation tables (see [02-domain-model.md](02-domain-model.md)):

```
QuestionVersion              # media_id, difficulty, status, authorship (language-neutral)
QuestionVersionTranslation   # (question_version_id, language) -> prompt, short_explanation
AnswerOption                 # position, is_correct (language-neutral)
AnswerOptionTranslation      # (answer_option_id, language) -> text, explanation
Rule                         # code, source_url, effective dates, version, status (neutral)
RuleTranslation              # (rule_id, language) -> title, text
QuestionMedia                # content hash, type, dimensions (neutral)
QuestionMediaTranslation     # (media_id, language) -> alt_text
```

There is **no** `text_uz` on `Rule` and **no** `alt_text_uz` on media — those are
translations. v1 writes only `language = "uz"` rows; Russian later adds `ru` rows against the
**same** base records. Media is shared across languages unless it bakes in text (avoid).

Because content text is keyed to the **immutable `QuestionVersion`** (and its options), a
translation added later attaches to a specific version; historical attempts remain rendered in
the language/version they were taken with.

## UI strings

- All user-facing strings go through a **single string catalog** (even with one language), so
  Russian is cheap to add.
- Frontend: a typed `uz` dictionary (e.g. `src/i18n/uz.ts`) via a small `t(key)` helper; a
  `lang` on the profile selects the catalog (always `uz` in v1).
- Backend user-facing messages (validation/error `detail`) are Uzbek and centralised.

## Copy conventions (Uzbek Latin)

- Orthography: o', g', sh, ch, ng.
- Terms: **YHQ**, **haydovchilik guvohnomasi**, **nazariy imtihon**, **chorraha**,
  **yo'l belgisi**, **to'xtash/to'xtab turish**.
- Result/dashboard: **O'tdingiz** / **Yiqildingiz**, **Imtihonga tayyorlik**,
  **Boshlang'ich daraja** (initial level), **Boshlang'ich natija** (diagnostic score),
  **Ma'lumot yetarli emas** (not enough data), **Xatolar**, **Imtihon rejimi** (exam mode).

## Non-goals (v1)

- No language switcher (single language).
- No auto-translation of content; Russian content later is human-authored/reviewed (LLM drafts
  allowed but verified — [06-content-plan.md](06-content-plan.md#llm-assistance-policy)).
